<task type="auto">
  <name>Task 1: Extend settings.sh for DoD rule parsing</name>
  <files>hooks/lib/settings.sh</files>
  <action>
Add DoD parsing to settings_load():

1. Parse `definition_of_done:` block from YAML frontmatter as multi-line list
   - Each line under `definition_of_done:` starting with `- ` becomes a rule
   - Store as newline-separated string in DEFINITION_OF_DONE

2. Parse `dod_enforcement:` value (advisory|strict, default: advisory)
   - Store in DOD_ENFORCEMENT

3. Export both variables for use by prompt.sh

Example config format in `.claude/redbull.local.md`:
```yaml
---
enabled: true
aggressiveness: high
dod_enforcement: advisory
definition_of_done:
  - Always run tests before stopping
  - Never stop mid-refactor
  - Ensure no TODO comments remain
---
```

Implementation notes:
- Reuse existing frontmatter parsing loop structure from settings.sh
- Handle multi-line YAML list (lines starting with `  - ` after `definition_of_done:`)
- Keep fail-closed: invalid/missing = empty DEFINITION_OF_DONE
- Set defaults in _settings_default(): DEFINITION_OF_DONE="" and DOD_ENFORCEMENT="advisory"
  </action>

- DOD_ENFORCEMENT is "advisory" or "strict"

  </verify>
  <done>
- settings_load() parses definition_of_done list and dod_enforcement from YAML

<task type="auto">
  <name>Task 2: Enhance prompt.sh for DoD injection</name>
  <files>hooks/lib/prompt.sh</files>
  <action>
Modify build_evaluation_prompt_with_rules() to append DoD section AFTER project rules:

1. After appending project rules, check if DEFINITION_OF_DONE is non-empty
2. If non-empty, append DoD section based on DOD_ENFORCEMENT mode:

**Advisory mode (default):**
```
---

DEFINITION OF DONE (consider these project completion criteria):

The user has defined these completion requirements. Factor them into your decision:

$DEFINITION_OF_DONE

If work appears incomplete according to these criteria and the assistant hasn't addressed them, lean toward continuing.
```

**Strict mode:**
```
---

DEFINITION OF DONE (HARD REQUIREMENTS):

The user has defined these MANDATORY completion criteria. These are NOT suggestions:

$DEFINITION_OF_DONE

STRONGLY BIAS toward should_continue=true if ANY of these criteria appear unmet. The assistant should NOT stop until these are addressed or explicitly acknowledged as out of scope.
```

Implementation notes:
- Source settings.sh at top of prompt.sh to access DEFINITION_OF_DONE and DOD_ENFORCEMENT
- DoD appends AFTER project rules (layered: base → rules → DoD)
- Empty DEFINITION_OF_DONE = no DoD section added (backward compatible)
  </action>

2. Strict mode: prompt contains "HARD REQUIREMENTS" and "STRONGLY BIAS"
3. Empty DoD: no DoD section in prompt (clean fallback)
  </verify>
  <done>
- DoD section appended after project rules when DEFINITION_OF_DONE is non-empty
- Advisory mode provides soft guidance
