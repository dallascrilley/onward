# REF-012 — Add scenario schema validation + normalization in eval runner

## Goal
Make scenario failures actionable by validating fixture shape before execution and normalizing minor formatting differences.

## Blockers / Dependencies
- None (can be built in parallel with REF-001, but coordinate any shared harness edits).

## Files
- `test/evals/run-evals.sh`
- `test/evals/scenarios/*.json` (only if normalization reveals broken fixtures)

## Work (Tasks)
1. Add a preflight validation step that checks required keys exist:
   - `name`, `description`, `expected_decision`, `transcript`
2. Validate `transcript` is an array of `{role, content}` objects (or normalize if currently mixed).
3. Fail fast with a clear message that points to the offending scenario file.

## Acceptance Criteria
- [ ] Invalid scenarios fail fast with clear errors.
- [ ] Existing scenarios still run without edits (unless truly invalid).
- [ ] No false-green behavior remains in the harness (coordinate with REF-001).

## Proving Commands
- `./test/evals/run-evals.sh`
